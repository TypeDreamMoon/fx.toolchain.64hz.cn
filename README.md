# fx.toolchain.64hz.cn — the DreamFXLang documentation site

中英文文档都在插件仓库维护。AI 配置留在本站，翻译 PR 开到插件仓库，人工合并后网站同步发布；见 [DOCS_SYNC.md](DOCS_SYNC.md)。

The manual for [DreamFX](https://github.com/TypeDreamMoon/DreamFX): text-first Niagara authoring for
Unreal Engine. Chinese is the default locale, English lives under `/en`.

Built on the same stack as its sister site [lang.64hz.cn](https://lang.64hz.cn) (DreamShaderLang):
Next.js + fumadocs, a static export, and rsync over SSH for CI deployment.

## Running it

```bash
npm install
npm run dev          # http://localhost:3000
npm run typecheck    # fumadocs-mdx codegen + tsc --noEmit
npm run build        # static export into out/
npm run preview      # serve out/
```

## Deploying

GitHub Actions uses incremental rsync deployment; see [DEPLOYMENT.md](DEPLOYMENT.md).
The commands below retain the existing local SFTP uploader:

```bash
cp .env.example .env       # fill in SFTP_PASSWORD or SFTP_KEY_PATH
npm run deploy:sftp        # build, then upload out/ to the web root
```

`upload.js` cleans the remote directory before uploading and preserves `.user.ini`, `.htaccess` and
`.well-known` — deleting the last one mid-renewal would break certificate issuance. It refuses any
remote directory outside `/www/wwwroot/`.

### GitHub Actions

`.github/workflows/deploy.yml` runs `npm ci → typecheck → build → check-links` on every push and pull
request, and syncs `out/` over SSH on a push to `main`/`master` (or a manual **Run workflow**).
Pull requests build and check but never deploy. Publishing branches share a concurrency group,
and an active deployment finishes before the next one starts. Select **dry_run** in a manual run
to compare without changing server files.

Repository secrets (Settings ▸ Secrets and variables ▸ Actions):

| Secret | Required | Value for this site |
| --- | --- | --- |
| `SFTP_PASSWORD` | **one of these two** | the SSH password |
| `SFTP_PRIVATE_KEY` | **one of these two** | the private key, whole PEM including the header/footer lines |
| `SFTP_PASSPHRASE` | only with an encrypted key | the key's passphrase |
| `SFTP_HOST` | recommended | `8.153.161.157` |
| `SFTP_PORT` | optional | `22` |
| `SFTP_USER` | recommended | `root` |
| `SFTP_REMOTE_DIR` | recommended | `/www/wwwroot/fx.toolchain.64hz.cn` |
| `SFTP_KNOWN_HOSTS` | only for a different host/port or host-key rotation | verified known-hosts entries; see [DEPLOYMENT.md](DEPLOYMENT.md) |

Host, port, user and remote directory keep the same fallback values in CI and the local uploader.
CI compares file contents, compresses transfers and delays deletion; it never clears the web root
before uploading. Both paths refuse targets outside `/www/wwwroot/` and preserve `.user.ini`,
`.htaccess` and `.well-known`.

The workflow fails fast with a named error when neither credential secret is set, rather than hanging
on an SSH connect.

### MDX components

Registered globally, so content never writes an import:

| | |
| --- | --- |
| `<Dfx sev msg raised />` | one diagnostic's generated half — severity pill, verbatim message, raise sites |

## The homepage

Five full-height bands — hero, source sample, workflow, tooling, docs — one per screen.

**Snapping is CSS**: `html:has(.dfx-home)` gets `scroll-snap-type: y mandatory` and each band a snap
point, so touch, the keyboard and a JavaScript-less page all work on their own. Below 660px of height
(or 720px of width) the snapping and the fixed dot rail switch themselves off and the page becomes an
ordinary scroll.

**Timing is JavaScript** (`app/_home/slide-deck.tsx`). `scroll-behavior: smooth` is deliberately not
set: with mandatory snapping the two animations fight — the browser glides, re-targets, then snaps
again — and that double motion is the stutter. Instead a gesture is animated on one 720ms
`easeInOutCubic`, with snapping suspended for the duration and handed straight back afterwards.
Measured over CDP with real wheel events: `0 → 749` in ~720ms, 1px steps at the ends and ~98px at the
middle, landing exactly on the snap position.

A trackpad swipe arrives as dozens of decaying wheel events, so anything within 160ms of the last one
is treated as the tail of a gesture that already moved: five notches 30ms apart advance one screen,
not five. A section taller than the viewport keeps native scrolling until its edge is reached.

Content **reveals on arrival** (fade + 20px rise, staggered for the workflow steps). Screens already
visible at hydration are marked instantly so nothing the reader can see ever flashes, and under
`prefers-reduced-motion` nothing is hidden in the first place.

The dot rail on the right is plain in-page anchors, and the deck intercepts their clicks to glide on
the same curve.

### The backdrop

Two layers, both decorative and both `aria-hidden`:

- **`Backdrop`** (server markup, CSS motion) — three soft lights and a slowly panning grid, fixed
  behind the whole deck. Only `translate`, `scale` and `opacity` animate, so every frame is a
  compositor job: no blur filter to re-run, no `background-position` repaint. The lights also
  re-place themselves per screen off `documentElement[data-screen]`, which `SlideDeck` sets — so
  advancing a screen moves the light as well as the content.
- **`Particles`** (canvas, hero only) — 90 drifting motes in the brand hues, reading the palette off
  the CSS custom properties so they follow the theme. It stops itself whenever it cannot be seen: tab
  hidden, hero scrolled away, or `prefers-reduced-motion` (one frame is drawn and left).

Measured in headless Chrome with the GPU off, during a glide: median frame 16.7ms, p95 33.4ms.

### The hero art

```bash
python scripts/prepare-art.py --plugin <path to Plugins/DreamFX>
```

Writes `public/art/character-{480,960}.webp` from the plugin's `Images/character.png`. Two things
about that source are worth knowing: its alpha covers **only the figure** — the blue backdrop and the
obelisk beside her live in the RGB of fully transparent pixels, so the export is a cutout — and a
plain RGBA downscale would smear that blue into her silhouette, which is why the script scales
premultiplied and bleeds the edge colour outward first.

## Updating diagnostics

Use [DOCS_SYNC.md](DOCS_SYNC.md): plugin `Docs/diagnostics/` supplies English, and `Docs/zh-CN/diagnostics/` supplies reviewed Chinese. AI runs from this website and opens PRs in the plugin repository; merged plugin documents are synchronized before publication. Website-only additions stay after `<!-- docs-sync:notes -->`. The old `scripts/diagnostics/sync.py` and its translation files are historical; do not use them to overwrite reviewed pages.

## Checking links

```bash
npm run build
python scripts/check-links.py
```

It validates every `/docs` link and `#anchor` against the export, and exits non-zero on a miss.
